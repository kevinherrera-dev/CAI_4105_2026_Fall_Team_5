THE ONE-SENTENCE VERSION

  challenge1_test.csv    2,467 apartments, rent HIDDEN.

  The ID column:             ID      (just a row number. NEVER use it

THE 6 STEPS

  STEP 1: LOOK AT THE DATA AND PREPARE IT
    - Open the training file. What columns exist? Which are numbers
      (like square feet) and which are words (like city)?
    - Any blanks? Fill them in (imputation).
    - Turn word columns into 0/1 columns (one-hot encoding).
    - Optionally put the number columns on the same scale (scaling).
    - The data is already mostly clean, so don't overthink this.

  STEP 2: PICK A FAIR WAY TO TEST (your "validation strategy")
    - Use 5-fold cross-validation ON THE TRAINING FILE ONLY.
    - Grade every model with RMSE (the typical $ miss; lower = better).
    - Put cleaning + model together in a Pipeline so nothing leaks.
    - Use the SAME folds and the SAME metric for every model so the
      comparison is fair.

  STEP 3: TRY THE 4 REQUIRED MODELS
    1. Linear Regression   (the best straight line, Module 3)
    2. Decision Tree       (yes/no question flowchart, Module 4)
    3. Random Forest       (many trees that vote/average, Module 4)
    4. Gradient Boosting   (trees in a row fixing mistakes, Module 4;
                            XGBoost is the version used in class)
    Make a TABLE of each model's cross-validation RMSE.
    Also note the training RMSE vs the validation RMSE. A big gap
    means overfitting.

  STEP 4: MAKE THEM BETTER
    - Grid Search: automatically tries combinations of settings
      (hyperparameters) and keeps the combo with the lowest CV RMSE.
    - Optional "feature engineering": build new clues out of the old
      ones (example: square feet per bedroom).

  STEP 5: PICK THE WINNER AND EXPLAIN WHY (a few sentences)
    Judge on:
      - lowest validation RMSE
      - not overfitting (train and validation scores are close)
      - how complicated it is
      - how slow it is to train
      - how easy it is to explain
    (Most likely winner: Gradient Boosting/XGBoost or Random Forest.)

  STEP 6: MAKE THE FINAL PREDICTIONS
    - Train the winner on ALL of the training file.
    - Predict the price for every row of challenge1_test.csv.
    - Save predictions.csv with exactly 2 columns:  ID, price
      (2,467 rows, one per test apartment).

 PART 2: DICTIONARY (in the order you'll meet the words)
=====================================================================

-- BASICS ------------------------------------------------------------

Machine learning (ML)
  Teaching a computer by showing it examples instead of writing
  rules. It finds the pattern between the clues and the answer.

Dataset / data
  A table (like an Excel sheet). Each ROW is one apartment. Each
  COLUMN is one piece of info about it.

Observation
  One row = one apartment.

Feature (also called predictor, variable or X)
  A CLUE column the model uses to guess: bedrooms, square feet,
  city... "X" is math's nickname for all the clue columns.

Target (also called y, label or outcome)
  The ANSWER column you want to predict. Here: price.

Numerical feature
  A clue that's a number (square feet = 850).

Categorical feature
  A clue that's a word or label (city = "Miami", pets = "yes").

Model
  The "guessing machine". A math recipe that turns clues into a
  guess.

Training / fitting (.fit() in code)
  The model "studying" the examples and adjusting itself until its
  guesses match the real answers as well as possible.

Prediction (.predict() in code)
  The model's guess for something. The goal is good guesses on NEW
  data.

Supervised learning
  Learning with an answer key: every training row has the right
  answer. This challenge is supervised.

Regression
  Supervised learning where the answer is a NUMBER (rent in $).
  This challenge is a regression problem. (The opposite is
  "classification", where the answer is a category like yes/no.
  The Lab 4&5 credit-approval notebook was classification.)

-- TESTING HONESTLY ----------------------------------------------------

Generalization
  How well the model does on data it has NEVER seen. This is the
  whole goal.

Overfitting
  The model MEMORIZED the training data, noise included. Great score
  on training, bad on new data. Like a student who memorized the
  practice test. Sign: training RMSE much lower (better) than
  validation RMSE.

Underfitting
  The model is too simple to even learn the training data. Bad on
  BOTH training and validation.

Noise
  Random flukes in the data that aren't a real pattern.

Train / validation / test split
  Training = homework (the model learns from it).
  Validation = practice quiz (compare and tune models).
  Test = final exam (opened once at the end).
  In this challenge, the TEACHER already locked the test set away
  (the hidden prices). You make your own validation using
  cross-validation on the training file.

Holdout validation
  Setting aside ONE chunk of the training data as the practice quiz.
  Simple, but one chunk can be lucky or unlucky.

Cross-validation (CV) / k-fold cross-validation
  Cut the training data into k slices (usually 5 = "5-fold"). Train
  on 4 slices and test on the 5th. Repeat 5 times so every slice gets
  a turn being the quiz. Average the 5 scores = a more trustworthy
  grade. The spread of the 5 scores = how consistent the model is.

Validation strategy
  Your chosen method for testing fairly (e.g., "5-fold CV on the
  training set, RMSE"). Use the SAME one for every model.

Data leakage
  Info the model shouldn't have sneaks into training. Example: you
  compute averages (for filling blanks or scaling) using ALL the data
  before splitting. Then your scores look better than they really
  are. Fix: learn every preprocessing step from training data only.
  Pipelines do this automatically during CV.

random_state
  A number (like 42) that makes "random" things (shuffling, splits,
  forests) come out the same every run, so your results are
  reproducible.

Reproducible
  Someone else can run your notebook and get the same results.

-- PREPARING THE DATA (preprocessing) --------------------------------

Preprocessing
  Cleaning and converting the data so models can use it.

EDA (Exploratory Data Analysis)
  "Looking around" the data first: column types, missing values,
  averages, min/max, weird values, how price is spread out.
  In code: df.head(), df.info(), df.describe(), df.isna().sum()

Missing values / NaN
  Blank cells. NaN = "Not a Number" = empty.

Imputation (SimpleImputer)
  Filling blanks with a sensible guess: the average (mean) or middle
  (median) for numbers, the most common value ("most_frequent") for
  categories.

Encoding / One-hot encoding (OneHotEncoder)
  Turning a word column into 0/1 columns. "City" with Miami/Tampa
  becomes two columns, City_Miami and City_Tampa, holding 1 or 0.
  handle_unknown="ignore" = don't crash if the test file has a city
  the training file never had.

Scaling / standardization (StandardScaler)
  Rewriting numbers as "how far above or below average", so every
  column is on the same ruler. Matters for Linear Regression.
  Trees don't really need it.

Outlier
  An extreme, unusual row (a $30,000/month penthouse). Linear
  Regression is sensitive to these. Trees handle them better.

Feature engineering
  Creating NEW clue columns from existing ones to help the model.
  Example: price is often skewed, so some people model log(price).
  Or sq_ft / bedrooms. Optional, but encouraged.

ColumnTransformer
  A scikit-learn tool that applies different preprocessing to
  different columns: number columns get imputer (+ scaler), word
  columns get imputer + one-hot.

Pipeline
  An assembly line that glues preprocessing + model into ONE object.
  You call .fit() once and everything happens in order. It's
  leak-proof inside cross-validation.

-- THE MODELS -----------------------------------------------------------

Baseline
  The simplest model to compare against. If a fancy model can't beat
  it, it isn't worth it. Linear Regression is a common baseline.

Linear Regression (LinearRegression)
  Finds the best straight line (or flat plane) through the data:
  price = b0 + b1*clue1 + b2*clue2 + ...
  The b's (called beta, or coefficients) are numbers the computer
  figures out. Simple and easy to explain, but it can only capture
  straight-line patterns.

Coefficient / beta (b)
  "How much the price changes when that clue goes up by 1."

Decision Tree (DecisionTreeRegressor)
  A flowchart of yes/no questions ("sq ft > 900?") ending in a guess.
  Easy to explain. Overfits easily if it grows too deep.

Random Forest (RandomForestRegressor)
  Hundreds of slightly different trees, each trained on a random
  sample of rows and clues. For regression, it AVERAGES their
  guesses. More stable and accurate than one tree.

Gradient Boosting (GradientBoostingRegressor or XGBRegressor)
  Trees built ONE AFTER ANOTHER. Each new tree learns to fix the
  leftover mistakes of the team so far. Usually the most accurate on
  spreadsheet data, but it has the most knobs to tune.
  XGBoost = "eXtreme Gradient Boosting", the popular version used in
  class.

Ensemble
  A model made of many models combined (Random Forest and Boosting
  are both ensembles).

Parametric vs non-parametric
  Parametric = assumes a fixed shape (Linear Regression assumes a
  straight line). Non-parametric = no fixed shape (trees).

Interpretability
  How easy it is for a human to understand WHY the model guessed
  what it did. Linear Regression and a single tree = high. Forest and
  boosting = low.

Variance (in the model sense)
  How jumpy a model is. Change the data a little and the model
  changes a lot. Single trees have HIGH variance. Forests reduce it.

-- GRADING THE MODELS -----------------------------------------------

Error / residual
  The miss for one row = real price minus guessed price.

Loss function
  The "ouch number" the model tries to shrink WHILE training. For
  regression it's usually MSE.

MSE (Mean Squared Error)
  Square each miss, then average them. Squaring makes big misses hurt
  a lot more.

RMSE (Root Mean Squared Error)  <-- YOUR MAIN METRIC
  The square root of MSE. It's back in DOLLARS, so roughly "the
  typical miss". RMSE = 300 means your guesses are usually off by
  about $300. LOWER = BETTER.

MAE (Mean Absolute Error)
  The average miss ignoring minus signs. Also in dollars.

R-squared (R2)
  0 to 1: how much of the ups and downs in price the model explains.
  1 = perfect, 0 = no better than always guessing the average price.

Evaluation metric
  The number humans use to judge the model (here: RMSE).

neg_root_mean_squared_error
  What scikit-learn calls RMSE inside cross_val_score / GridSearchCV.
  It's NEGATIVE because scikit-learn always maximizes scores. Just
  flip the sign: -(-312.5) = RMSE of 312.5.

-- TUNING ------------------------------------------------------------

Hyperparameter
  A setting YOU choose BEFORE training (the model does not learn it).
  Like the oven temperature. Examples:
    max_depth          how many questions deep a tree can go
    min_samples_leaf   minimum rows allowed in a tree's final box
    n_estimators       how many trees (forest / boosting)
    learning_rate      how much each boosting tree is trusted
                       (small = careful)
    subsample / colsample_bytree   use a random % of rows / columns
                       per tree (XGBoost)

Hyperparameter tuning
  Trying different settings to find the best ones.

Grid Search (GridSearchCV)
  You give a list of values for each setting. It tries EVERY
  combination using cross-validation and reports the best combo
  (.best_params_) and its score (.best_score_). refit=True then
  retrains the best combo on all the training data
  (.best_estimator_).
  Warning: 3 x 3 x 3 = 27 combos x 5 folds = 135 trainings. Big
  grids get slow.

Regularization
  A "keep it simple" penalty that fights overfitting. Ridge and Lasso
  are regularized versions of linear regression.

Computational requirements
  How much time and computer power the model needs.

-- SUBMISSION WORDS ---------------------------------------------

Jupyter notebook (.ipynb)
  A document of code "cells" you run one at a time. The output shows
  under each cell.

GitHub repo (repository)
  Your team's online project folder with full version history.
  commit = save a snapshot with a message.
  push = upload your commits to GitHub.

README.md
  The front-page text of the repo, written in Markdown (simple
  formatting: # for headings, - for bullets).

requirements.txt
  A list of libraries (pandas, scikit-learn, xgboost...) and versions
  so others can install the same setup. Make it with:
  pip freeze > requirements.txt

CSV
  "Comma-separated values". A plain spreadsheet file.

predictions.csv
  Your output file: columns ID and price, one row per test apartment.
